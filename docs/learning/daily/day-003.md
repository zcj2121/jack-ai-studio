# Day 3：用 React 构建第一个产品首页

## 今日目标

1. 理解 React Component、JSX、Props 和 State。
2. 能用 Vue 经验对照 React 的基本开发方式。
3. 把默认 Next.js 页面改造成 Jack AI Studio 最小产品首页。
4. 区分 Server Component 与 Client Component。
5. 通过按钮交互观察 State 如何驱动界面更新。

今天只实现首页展示与一个局部交互，不开发真实 Dashboard、Chat、路由跳转或接口请求。

## 必备理论

### 1. Component（组件）

**专业解释：**

Component 是封装界面结构、样式和行为的可复用 UI 单元。React Component 通常是返回 JSX 的函数。

**大白话：**

它和 Vue 组件解决的是同一个问题：把复杂页面拆成职责清楚的小模块。区别在于 React 常用 TypeScript 函数直接表达组件。

**举例：**

`FeatureCard` 负责展示一个产品模块，首页只需要传入标题、描述和状态，不必重复卡片结构。

**在 Jack AI Studio 中的作用：**

今天抽取 `FeatureCard` 和 `WorkspaceViewToggle`。后续 Chat 消息、Provider 选择器等也会拆成组件。

### 2. JSX（JavaScript Syntax Extension，JavaScript 语法扩展）

**专业解释：**

JSX 允许在 JavaScript 或 TypeScript 中编写类似 HTML 的声明式 UI，最终会被编译为 React 元素创建代码。

**大白话：**

Vue 把模板放在 `<template>` 中，React 更习惯把模板结构直接写在函数的 `return` 里。它看起来像 HTML，但能够直接使用 JavaScript 表达式。

**举例：**

```tsx
<h2>{title}</h2>
```

花括号中的 `title` 是 JavaScript 表达式，不是字符串模板语法。

**在 Jack AI Studio 中的作用：**

首页通过 JSX 组合 Header、Hero、功能卡片和交互按钮。

### 3. Props（属性参数）

**专业解释：**

Props 是父组件传给子组件的只读输入，用来配置组件的内容和行为。

**大白话：**

它与 Vue Props 很接近：父组件下发数据，子组件负责展示。子组件不应该直接修改传入的数据。

**举例：**

```tsx
<FeatureCard title="AI Chat" status="Sprint 2" />
```

`FeatureCardProps` 使用 TypeScript 明确每个字段的类型，避免无意义的 `any`。

**在 Jack AI Studio 中的作用：**

首页用同一个卡片组件渲染 AI Chat、Knowledge 和 Agent Center 三个模块。

### 4. State（状态）

**专业解释：**

State 是组件内部会随用户操作或业务事件变化的数据。State 更新后，React 会重新执行组件渲染并更新需要变化的 DOM。

**大白话：**

可以把 `useState` 类比成 Vue 的 `ref`：它保存响应式数据，修改后界面自动变化。但 React 不能直接给旧值赋值，需要调用对应的 setter 函数。

**举例：**

```tsx
const [activeView, setActiveView] = useState("learning");
```

点击“产品视图”时调用 `setActiveView("product")`，页面说明随之更新。

**在 Jack AI Studio 中的作用：**

今天只管理一个局部视图切换。未来输入框、弹窗和选择器也会有局部 State；跨页面状态会在确有需要时再设计。

### 5. Server Component 与 Client Component

**专业解释：**

Next.js App Router 的页面和布局默认是 Server Component。只有需要 State、事件处理、生命周期或浏览器 API 的组件才需要通过 `"use client"` 声明为 Client Component。

**大白话：**

静态内容尽量在服务器准备好；只有真正需要点击交互的“小岛”才把 JavaScript 发送给浏览器。

**举例：**

`page.tsx` 只组合静态结构，保持 Server Component；`WorkspaceViewToggle` 使用 `useState` 和 `onClick`，因此是 Client Component。

**在 Jack AI Studio 中的作用：**

这种边界能减少浏览器 JavaScript，也避免把 API Key 等服务端能力带到客户端。

## Python 学习

今天没有新增 Python 代码。可以先建立一个跨语言类比：

```tsx
type FeatureCardProps = {
  title: string;
};
```

未来 Python 也会通过 type hints（类型提示）描述函数输入。两者语法不同，但目标一致：让数据契约更清晰，让编辑器和检查工具更早发现错误。

## 项目实战

### 组件结构

```text
src/
├── app/
│   ├── globals.css
│   ├── layout.tsx
│   └── page.tsx
└── components/
    ├── feature-card.tsx
    └── workspace-view-toggle.tsx
```

### 数据流

```text
page.tsx 中的 features
        ↓ Props
FeatureCard 展示内容

用户点击按钮
        ↓ onClick
setActiveView 更新 State
        ↓ 重新渲染
说明文字发生变化
```

### 设计方向

首页采用深色工程控制台风格，以荧光信号色表达“系统在线”和训练进度。设计服务于开发者 Workspace 定位，没有引入图片、图标库或动画依赖。

## 关键代码说明

- `FeatureCardProps` 导出为公共类型，首页数据与组件输入共享同一个契约。
- `features.map(...)` 类似 Vue 的 `v-for`，每一项使用稳定的 `index` 作为 key。
- `WorkspaceView` 使用字符串联合类型，只允许 `learning` 或 `product`。
- `aria-pressed` 表达切换按钮的当前状态，`aria-live` 让辅助技术感知说明文字变化。
- Client Component 边界只包裹交互区域，不把整个首页变成客户端组件。

## 今日英文术语

1. **Component**：组件，可复用 UI 单元。
2. **JSX**：在 JavaScript / TypeScript 中描述 UI 的语法扩展。
3. **Props**：父组件传给子组件的只读输入。
4. **State**：组件内部会变化并驱动界面更新的数据。
5. **Render**：根据数据生成界面描述的过程。
6. **Event Handler**：响应点击、输入等事件的处理函数。
7. **Server Component**：主要在服务器执行的 React 组件。
8. **Client Component**：可在浏览器中处理交互的 React 组件。
9. **Hydration**：React 为已有 HTML 绑定交互能力的过程。
