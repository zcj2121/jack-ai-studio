## 必备理论

### 1. Automated Test（自动化测试）

**专业解释：**

Automated Test 是由程序自动准备输入、执行目标代码并验证实际结果是否符合预期的检查。

**大白话：**

它把人工验收步骤写成机器可以重复批改的题。以后代码变化后，不必只靠记忆重新检查所有旧功能。

**举例：**

```python
service_status = await get_health()
self.assertEqual(service_status.status, "foundation ready")
```

**在 Jack AI Studio 中的作用：**

今天保护 Health 契约；以后 Chat、Provider、RAG 和 Agent 都需要分层自动测试。

### 2. Unit Test（单元测试）

**专业解释：**

Unit Test 聚焦一个较小的代码单元，在尽量少的外部依赖下验证其行为。

**大白话：**

像单独检查一个 Vue Composable 或工具函数，而不是启动整套前后端再操作浏览器。

**举例：**

今天直接 `await get_health()`，验证它返回可信的 `ServiceStatus`。

**在 Jack AI Studio 中的作用：**

当前用于快速验证路由函数和注册契约。它不经过真实网络，因此不能替代 Day 9 的 HTTP Integration Test。

### 3. Regression（回归）

**专业解释：**

Regression 指已有正确功能被后续代码改动意外破坏。

**大白话：**

新功能做成功了，但昨天能用的 Health Endpoint 被改坏了，这就是回归。

**举例：**

如果未来误删 `/health` 或把 Method 改成 POST，路由注册测试会失败。

**在 Jack AI Studio 中的作用：**

从 Sprint 2 开始代码会更复杂，回归测试能持续保护 Sprint 1 建立的基础。

### 4. Assertion（断言）

**专业解释：**

Assertion 明确声明程序结果必须满足的条件；条件不成立时，测试失败并给出定位信息。

**大白话：**

它是自动批改题的标准答案，例如“返回值必须是 `ServiceStatus`”“路由必须支持 GET”。

**举例：**

```python
self.assertIn("GET", route.methods)
```

**在 Jack AI Studio 中的作用：**

断言把模糊的“看起来能用”转换成可执行、可失败的质量标准。

### 5. Quality Gate（质量门禁）

**专业解释：**

Quality Gate 是提交、合并或发布前必须全部通过的一组自动化检查。

**大白话：**

它像机场安检：ESLint、TypeScript、Build、Python 编译和测试都是不同检查口，只要一个失败就不能算整体通过。

**举例：**

```bash
pnpm check:foundation
```

**在 Jack AI Studio 中的作用：**

今天先建立本地质量门禁；未来 CI/CD 会在 GitHub Actions 中执行相同思想的检查。

### 6. Exit Code（退出码）

**专业解释：**

Exit Code 是进程结束时返回给操作系统的整数。通常 `0` 表示成功，非 `0` 表示失败。

**大白话：**

命令不仅输出文字，还会用一个机器可读的“红灯或绿灯”告诉后续流程是否继续。

**举例：**

`check:foundation` 使用 `&&` 串联命令；前一项返回非零 Exit Code，后续项不会继续执行。

**在 Jack AI Studio 中的作用：**

未来 CI 可以根据 Exit Code 自动阻止不合格代码合并或部署。

## Python 学习

### unittest 与前端测试经验对照

| Python `unittest` | Vitest / Jest |
| --- | --- |
| `IsolatedAsyncioTestCase` | `describe` 中的异步测试环境 |
| `test_...` 方法 | `it(...)` / `test(...)` |
| `self.assertEqual(...)` | `expect(...).toBe(...)` |
| `self.assertIsInstance(...)` | `expect(...).toBeInstanceOf(...)` |
| `python -m unittest` | `vitest run` / `jest` |

`IsolatedAsyncioTestCase` 会为每个异步测试提供隔离的 Event Loop（事件循环），因此可以直接 `await get_health()`。

## 今日英文术语

1. **Automated Test**：由程序自动执行和判断结果的测试。
2. **Unit Test**：验证较小代码单元的测试。
3. **Integration Test**：验证多个模块或服务协作的测试。
4. **Regression**：后续改动破坏已有功能。
5. **Assertion**：声明结果必须满足的条件。
6. **Test Case**：一个独立的测试场景。
7. **Test Runner**：发现并执行测试的程序。
8. **Quality Gate**：必须全部通过的一组质量检查。
9. **Exit Code**：命令结束时返回的成功或失败状态。
10. **CI**：持续集成，自动执行构建和测试的工程流程。
