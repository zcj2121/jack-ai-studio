## 必备理论

### 1. 什么是 AI 应用

AI 应用不是把聊天框直接连接到模型 API。一个可维护的 AI 产品通常由以下部分共同组成：

- 前端：接收输入、展示消息和执行状态。
- 后端：保护 API Key、处理业务规则、记录日志和访问数据。
- 模型服务：根据 Prompt 和上下文执行推理。
- 数据层：保存用户、会话、消息和知识库数据。
- 评估与安全：判断输出质量，并控制工具、文件和网络访问风险。

可以把它类比为熟悉的企业后台系统：LLM 是一种新的外部能力，类似支付或地图服务；它很重要，但不能替代前端、后端、权限、数据和监控。

### 2. AI 应用与传统程序的区别

传统函数通常对相同输入给出稳定、可预测的输出。LLM 输出具有概率性，同一个问题可能得到不同措辞甚至不同质量的答案。因此 AI 应用还需要：

- 管理 Prompt 和上下文。
- 校验模型输出，而不是默认它永远正确。
- 记录调用过程，便于调试和评估。
- 对高风险工具调用增加权限控制和人工确认。

### 3. 一次基础模型请求如何工作

最小链路如下：

```text
用户输入 → 前端 → 后端 → Provider API → LLM 推理 → 后端 → 前端展示
```

### 4. 五个基础概念

#### 4.1 LLM（Large Language Model，大语言模型）

**专业解释：**

一种基于海量文本训练的神经网络模型，能够理解并生成自然语言。

**大白话：**

可以先把它理解成 **AI 的语言大脑**。ChatGPT、Claude、Gemini、DeepSeek 等产品背后都使用了大语言模型。

**举例：**

你输入“用 Vue 开发经验解释 React State”，LLM 会结合输入内容生成一段新的解释。

**在 Jack AI Studio 中的作用：**

它是 Chat、RAG 和 Agent 的模型基础。Day 1 只理解概念，Sprint 2 才开始接入。

#### 4.2 Prompt（提示词）

**专业解释：**

发送给模型的指令、背景、上下文和输出约束。

**大白话：**

就像给一位能力很强的新同事写 **任务说明书**。说得越清楚，他越容易交付你想要的结果。

**举例：**

“介绍 TypeScript”比较模糊；“面向 Vue 开发者，用 3 个要点解释 TypeScript 泛型，并给出代码示例”更明确。

**在 Jack AI Studio 中的作用：**

未来 Chat 和 Prompt Library 会保存、组织并复用 Prompt。当前阶段只掌握它的组成。

#### 4.3 Token（词元）

**专业解释：**

模型读取和生成文本时使用的基本计算单位。

**大白话：**

就是 **AI 数字世界里的“字数”**。AI 不是严格按汉字或英文单词计数，而是按 Token 计数。

**举例：**

“今天天气不错。”在人眼里是几个汉字和标点，在不同模型眼里可能会被拆成不同数量的 Token，因此 Token 数不能简单等同于字数。

**在 Jack AI Studio 中的作用：**

Token 会影响请求费用、响应速度和可携带的对话内容，未来需要记录模型用量。

#### 4.4 Context Window（上下文窗口）

**专业解释：**

模型单次请求能够处理的输入与输出 Token 总量范围。

**大白话：**

它像 AI 面前的一张 **有限大小的办公桌**。系统指令、历史消息、用户问题和模型回答都要放在这张桌子上，放不下时就必须整理或移走旧内容。

**举例：**

一段对话持续很久后，如果把所有历史消息都发送给模型，可能超过窗口上限，需要截断、总结或检索相关内容。

**在 Jack AI Studio 中的作用：**

它决定会话历史如何管理，也是后续 Conversation Memory 和 RAG 设计的重要约束。

#### 4.5 Inference（推理）

**专业解释：**

使用已经训练好的模型，根据当前输入计算并生成结果的过程。

**大白话：**

训练像一个人长期 **上学学习**，推理像他学完之后 **现场回答问题**。Jack AI Studio 做的是组织问题并调用模型回答，不是从头培养一个大模型。

**举例：**

用户发送问题后，Provider 调用已有模型生成答案，这次生成过程就是一次 Inference。

**在 Jack AI Studio 中的作用：**

每次模型请求都会触发推理。项目关注推理调用、上下文、输出校验和成本，不训练基础模型。

## 今日英文术语

1. **AI Application**：AI 应用，由模型、业务逻辑、数据和界面共同组成的产品。
2. **Large Language Model (LLM)**：大语言模型，负责理解与生成文本。
3. **Prompt**：提示词，发送给模型的任务和上下文。
4. **Token**：词元，模型处理文本的基本单位。
5. **Context Window**：上下文窗口，一次请求可处理的 Token 范围。
6. **Inference**：推理，使用已训练模型生成结果的过程。
7. **Provider**：模型服务提供方，对外提供模型 API。
8. **API**：应用程序编程接口，系统之间交换数据的约定。

## 今日总结

- AI 应用是由前端、后端、数据层、模型服务、评估和安全共同构成的完整系统，不只是聊天框或单次模型调用。
- API Key 必须保存在后端，因为前端代码和网络请求对用户可见，无法安全保存密钥。
- Training（训练）是使用大量数据优化模型参数的过程；Inference（推理）是使用已有模型根据输入生成结果的过程。
- Context Window 有容量上限，对话过长时可能超限，需要截断、摘要或选择相关上下文。
- 基础请求链路是：用户输入 → 前端 → 后端 → Provider API → LLM → Provider API → 后端 → 前端展示。未来可使用 SSE 实现流式返回。
- Python 主要承担 FastAPI 后端、模型调用、RAG、Agent 和 MCP 等服务端能力；选择它的关键原因是 AI 生态成熟。
