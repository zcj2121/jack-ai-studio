## 必备理论

### 1. Server-side Fetch（服务端请求）

**专业解释：**

Server-side Fetch 是在 Next.js Server Component 的服务端渲染过程中发起 HTTP 请求，再把结果渲染成页面内容。

**大白话：**

浏览器先找 Next.js，Next.js 再作为“服务端中间人”访问 FastAPI。它类似 Nuxt SSR 在服务端获取数据，而不是让浏览器直接跨域请求。

**举例：**

```ts
const response = await fetch(`${apiBaseUrl}/health`)
```

**在 Jack AI Studio 中的作用：**

今天用于建立第一条前后端链路。后续敏感配置和服务端数据也可以停留在服务端边界，不进入浏览器 Bundle。

### 2. API Client（API 请求封装）

**专业解释：**

API Client 是集中管理服务地址、请求选项、响应类型和错误处理的代码边界。

**大白话：**

它类似 Vue 企业后台里的统一 `request.ts`：页面只关心“获取健康状态”，不用到处拼 URL 和重复写错误处理。

**举例：**

```ts
const apiHealth = await getApiHealth()
```

**在 Jack AI Studio 中的作用：**

今天只封装一个 Health 请求。后续增加 Chat API 时继续按业务边界扩展，不提前做复杂通用 SDK。

### 3. Environment Variable（环境变量）

**专业解释：**

Environment Variable 将随运行环境变化的配置从源码中分离。Next.js 中不带 `NEXT_PUBLIC_` 前缀的变量默认只在服务端可用。

**大白话：**

API 地址写在部署环境的配置单里，而不是焊死在业务代码中。开发、测试和生产可以使用不同地址。

**举例：**

```text
API_BASE_URL=http://127.0.0.1:8000
```

**在 Jack AI Studio 中的作用：**

今天配置 FastAPI 地址。未来 API Key 也必须只存在服务端环境变量中，但本 Day 不接入任何 Key。

### 4. Graceful Degradation（优雅降级）

**专业解释：**

Graceful Degradation 指依赖服务异常时，系统仍保留可用的基础界面，并向用户提供明确、可恢复的状态。

**大白话：**

FastAPI 没启动时，首页不白屏，而是显示 Offline，并提示启动后刷新重试。

**举例：**

`fetch` 超时、网络错误、非 2xx 状态码或错误 JSON 结构都会转换为可展示的 Offline 状态。

**在 Jack AI Studio 中的作用：**

未来模型 Provider、RAG 和 Tool 都可能暂时失败。明确的降级状态比吞掉错误或让整页崩溃更可靠。

### 5. Type Guard（类型守卫）

**专业解释：**

Type Guard 是在运行时检查未知值，并让 TypeScript 在条件成立后缩小类型范围的函数。

**大白话：**

`interface` 只告诉编辑器“我希望数据长这样”；Type Guard 像收到快递后真正开箱核对字段，避免相信外部 JSON。

**举例：**

```ts
function isServiceStatus(value: unknown): value is ServiceStatus
```

**在 Jack AI Studio 中的作用：**

今天用于守住 FastAPI 到 Next.js 的数据边界。它与 Day 7 的 Pydantic 形成前后呼应：两端都不盲信外部数据。

## 项目实战

### 当前完整链路

```text
浏览器请求首页
      ↓
Next.js Server Component
      ↓ GET /health
Uvicorn → FastAPI → Pydantic ServiceStatus
      ↓ HTTP 200 + JSON
Next.js Type Guard
      ↓
首页渲染 Online / Offline 状态
```

### 启动顺序

终端一：

```bash
uv run uvicorn app.main:app --app-dir apps/api --host 127.0.0.1 --port 8000
```

终端二：

```bash
pnpm dev:web
```

访问 `http://127.0.0.1:3000`。

## 关键代码说明

- `Home` 改为 `async` Server Component，可以直接 `await getApiHealth()`。
- `connection()` 表示以下内容在真实请求到达后运行，避免构建阶段固化 API 状态和运行时环境变量。
- `API_BASE_URL` 没有 `NEXT_PUBLIC_` 前缀，因此不会被打入浏览器 JavaScript。
- `cache: "no-store"` 每次页面请求都读取当前 Health 状态。
- 两秒超时避免后端异常时长期阻塞首页。
- `response.ok` 检查 HTTP 状态；`isServiceStatus` 检查 JSON 结构。
- `ApiHealth` 使用 Discriminated Union（可辨识联合类型）区分 Online 与 Offline，组件无需使用 `any`。

## 今日英文术语

1. **Server-side Fetch**：服务器渲染阶段发起的数据请求。
2. **API Client**：集中封装 API 请求与响应处理的代码边界。
3. **Environment Variable**：由运行环境提供的外部配置。
4. **Graceful Degradation**：依赖异常时仍保持基础可用的降级策略。
5. **Type Guard**：运行时检查并缩小 TypeScript 类型范围的函数。
6. **Unknown**：尚未验证、不能直接访问字段的安全类型。
7. **Timeout**：请求等待超过限定时间后主动终止。
8. **No-store**：不持久缓存本次 Fetch 响应。
9. **Runtime**：程序实际运行的阶段和环境。
10. **Discriminated Union**：通过共同字面量字段区分分支的联合类型。
